# Compounding pillars — full statements (internal reference)

Task-agnostic generalization of the principle that work should accrue rather than decay.
These are the substance the skill instantiates for a specific project. They are universal —
they apply to engineering, writing, design, research, and operations alike.

1. **The compounding axiom.** The single test for any process: *does each unit of work make the
   next one easier or harder?* If harder, you are accumulating debt. If easier, you are
   compounding. Every decision in the map below should push toward "easier."

2. **The loop is the unit of work.** Frame → Do → Review → Capture → Repeat. Ordinary work stops
   at "Do" (or "Review"). Compounding work always reaches **Capture** — the deliberate act of
   leaving behind something reusable. The loop scales: the same five steps govern a five-minute
   fix and a multi-week initiative.

3. **Invest in the system, not just the instance.** Split effort between *shipping the instance*
   and *improving the machine that ships instances* (reusable templates, automated checks,
   generators, playbooks, better context). The leverage heuristic: if a task will recur, the
   first time you do it is also the time to make the second time cheap.

4. **Encode judgment into durable artifacts.** Quality you currently supply by hand — taste,
   standards, rejected alternatives — should be written down where the system reads it
   automatically, so it produces work you approve rather than work you must fix.

5. **Teach once, reuse forever.** Context (background, constraints, conventions) given to the
   system is an asset with compounding returns. Re-deriving the same context every time is the
   most common silent tax on knowledge work.

6. **Build safety nets, not gatekeeping.** If you do not trust the output, the fix is better
   verification infrastructure (tests, automated review, monitoring, easy reversal), not more
   manual inspection. Safety nets scale; manual gatekeeping does not.

7. **Parallelize independent work.** Explicitly separate what can run concurrently from what is
   genuinely sequential. The bottleneck in compounding systems is usually coordination, not effort.

8. **The durable artifact is the source of truth.** A written plan, spec, or anchor outlives
   memory, survives handoffs, and steers everything downstream. Fixing the idea on paper is far
   cheaper than fixing the built thing.

9. **Capture learnings as retrievable atoms.** Small, self-contained, tagged notes — one insight,
   playbook, correction, or pattern each. Filter hard: a few high-signal atoms beat many noisy ones.

10. **Close the discoverability loop.** A captured learning only compounds if future work finds
    it. Every capture must update an index/pointer so the next person or agent surfaces it
    automatically, without being told it exists.

11. **Maintain against rot.** Learnings and assets decay as the project changes. On a cadence,
    decide for each: keep, update, replace, or archive. Surface corrections most prominently;
    flag low-confidence or stale items.
